# FarmEasy Technical Communication & Data Flow 📡

This document explains how your project's three main layers (Frontend, Backend, and Database) communicate with each other. Use this to explain your project's "Architecture" during evaluation.

---

## 1. The Architecture (3-Tier)
Your project follows the **Client-Server Architecture**:
1.  **Frontend (UI)**: Built with **React.js**. It's what the user sees and interacts with.
2.  **Backend (API)**: Built with **Node.js & Express.js**. It's the middleman that handles logic, security, and data processing.
3.  **Database (Data)**: **MySQL (Aiven Cloud)**. It stores all permanent information.

---

## 2. Advanced Integrations & Communication Flows

### A. Media Storage (Frontend → Backend → AWS S3)
When a user uploads a product image or review photo:
1.  **Frontend**: User selects a file. Frontend sends it to the Backend using `FormData`.
2.  **Backend**: Uses the `aws-sdk` and `multer` to stream the image directly to an **Amazon S3 Bucket**.
3.  **Database**: We don't store the "heavy" image in MySQL. Instead, S3 returns a **Public URL** (e.g., `https://s3.amazonaws.com/image.jpg`), which we save in the `product_image` or `review_images` column in MySQL.
4.  **UI**: When loading the page, the browser simply follows that URL to display the image.

### B. Payment Gateway (Frontend → Razorpay → Backend)
For secure checkouts:
1.  **Frontend**: User clicks "Pay Now". Frontend calls the Backend to "Create an Order" in Razorpay.
2.  **Backend**: Communicates with **Razorpay API** to get a unique `order_id`.
3.  **Frontend**: Opens the **Razorpay Checkout Overlay**. User pays.
4.  **Verification**: Razorpay sends a payment signature. The Backend verifies this signature to ensure the payment is authentic before updating the `orders` table to `status = 'paid'`.

### C. GST Verification (Frontend → Cashfree → Backend)
To ensure only real vendors join the platform:
1.  **Backend**: Takes the GST number provided during registration.
2.  **External API**: Backend calls the **Cashfree Verification API**.
3.  **Result**: Cashfree returns the legal business name and status.
4.  **Database**: If valid, the `seller` table is updated with the verified business details.

### D. Review & Rating System (Real-time Sync)
To keep the UI fast, we use a "Summary Sync" logic:
1.  **Action**: User submits a review to the `product_reviews` table.
2.  **Trigger**: The Backend controller immediately triggers a recalculation.
3.  **Summarization**: It updates the `product_rating_summary` table (5-star count, average rating, etc.).
4.  **UI Benefit**: When other users browse, they see the pre-calculated rating instantly without the database having to count thousands of rows every time.

### E. Vendor Dashboard Updates
The dashboard is a "Command Center" for sellers:
1.  **Live Analytics**: When a seller opens the dashboard, the Backend runs "Aggregate Queries" (using `COUNT`, `SUM`, `AVG`).
2.  **Data Sync**: It fetches data from `order_items`, `products`, and `vendor_reviews` to show:
    *   **Total Revenue**: Sum of all successful orders.
    *   **Order Count**: Total orders in the last 30 days.
    *   **Performance**: Average star rating from the `vendor_rating_summary` table.
3.  **Automatic Updates**: Every time a sale happens or a review is left, these numbers update automatically in the dashboard UI.

### F. Email Communication (SMTP/Nodemailer)
For notifications and security:
1.  **Trigger**: User registers or places an order.
2.  **Backend**: Uses the `nodemailer` library with an **SMTP Server** (like Gmail or SendGrid).
3.  **Communication**: Backend connects to the SMTP server using secure credentials from `.env`.
4.  **Delivery**: The SMTP server sends the email (OTP, Order Confirmation) to the user's inbox.
5.  **OTP Logic**: For registration, the Backend generates a 6-digit code, saves it in the `registration_otps` table, and emails it. The user enters it in the UI, and the Backend verifies it against the database.

---

## 3. Why this communication is Secure?
*   **Environment Variables (.env)**: All API keys for AWS, Razorpay, Cashfree, and SMTP are hidden in the backend and never exposed to the browser.
*   **JWT Authentication**: Every request to the Dashboard or Cart must have a valid JSON Web Token, ensuring users can only see their own data.
*   **SQL Injection Protection**: We use "Prepared Statements" to prevent hackers from manipulating the database through input fields.
